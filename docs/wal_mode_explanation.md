# SQLite WAL模式详解

## 传统模式 (DELETE/TRUNCATE Journal Mode)

```
数据库文件 <-> 日志文件
     ↓           ↓
   读写操作    临时存储变更
     ↓           ↓
   需要锁定    阻塞其他操作
```

**问题：**
- 写操作时整个数据库被锁定
- 读操作被写操作阻塞
- 并发性能差

## WAL模式 (Write-Ahead Logging)

```
数据库文件 <- WAL文件 <- 新写入
     ↓         ↓         ↓
   读操作   写操作    不冲突
     ↓         ↓         ↓
  不被阻塞   不阻塞读   高并发
```

**优势：**
- 读操作不被写操作阻塞
- 多个读操作可以并发执行
- 写操作只阻塞其他写操作，不阻塞读操作
- 显著提高并发性能

## 实现细节

### 1. 文件结构
```
database.db      # 主数据库文件
database.db-wal  # WAL文件（写日志）
database.db-shm  # 共享内存文件（索引）
```

### 2. 工作原理
1. **写操作**：新数据先写入WAL文件
2. **读操作**：从主文件和WAL文件组合读取
3. **检查点**：定期将WAL内容合并到主文件

### 3. 并发特性
- **读-读**：完全并发，无锁定
- **读-写**：不冲突，可以并发
- **写-写**：串行执行，但不影响读操作

## 性能提升对比

| 操作类型 | 传统模式 | WAL模式 | 性能提升 |
|---------|---------|---------|----------|
| 单纯读取 | 快 | 快 | 相似 |
| 读写混合 | 慢（阻塞） | 快（并发） | 5-10x |
| 高并发读 | 慢（串行） | 快（并发） | 10-50x |
| 批量写入 | 中等 | 快 | 2-3x |

## 配置参数说明

```sql
PRAGMA journal_mode=WAL;          -- 启用WAL模式
PRAGMA synchronous=NORMAL;        -- 平衡性能和安全性
PRAGMA cache_size=1000;           -- 增加缓存页数
PRAGMA temp_store=memory;         -- 临时表存储在内存
```
