# 模型推理后端独立 · 拆分设计

> 创建时间：2026-09-08
> 状态：设计阶段，待确认后实施
> 目标：主后端启动从 ~5-8s 降至 ~1-2s；推理服务故障不拖垮主后端

---

## 1. 问题根因

| 事实 | 数据 |
|------|------|
| 模型是懒加载 | `_try_load` + `_load_attempted`，启动不加载 jina |
| 启动慢主因 | `import torch+transformers+sentence_transformers` = **3.27s** |
| 对照 | 纯 fastapi import = 0.13s |
| 整体启动 | ~5-8s（Python + FastAPI + DB + 连接池） |

**结论**：慢的不是模型加载，是深度学习库的 import 开销。拆分后主后端不再 import 这些库。

---

## 2. 目标架构

```
┌─────────────────┐     HTTP      ┌──────────────────┐
│   前端 (Vite)   │──────────────▶│  主后端 (FastAPI) │
│  localhost:5173 │               │   CRUD/文件/标签  │
└─────────────────┘               │   搜索编排        │
                                  │   视觉模型API调用  │
                                  └────────┬─────────┘
                                           │ HTTP /encode
                                           ▼
                                  ┌──────────────────┐
                                  │ 推理服务 (FastAPI) │
                                  │  持有 jina 模型   │
                                  │  GPU/CUDA         │
                                  └──────────────────┘
```

**拆分边界**：
- 推理服务：只做"编码"（图/文 → 向量），持有 jina-embeddings-v4 模型
- 主后端：CRUD、文件存储、标签、搜索编排、视觉模型调用（云端 glm-4.6v-flash）
- 向量存储（sqlite-vec）：留在主后端，只有"编码"这一步走出去

## 3. 推理服务接口定义

独立 FastAPI 应用，建议放在 `backend/inference_service/` 或独立目录。

### 3.1 健康检查

```
GET /health
→ 200 { "status": "ok", "model_loaded": true, "dimension": 2048 }
→ 503 { "status": "unavailable", "error": "模型目录不存在" }
```

### 3.2 编码接口

```
POST /encode
Content-Type: application/json

请求：
{
  "input_type": "text" | "image",   // 编码类型
  "inputs": ["文本1", "文本2"],      // text 模式
  // 或
  "image_paths": ["/path/to/img.jpg"],  // image 模式（服务端本地路径）
  // 或
  "image_base64": ["base64..."],    // image 模式（base64，小图用）
  "normalize": true                  // 是否 L2 归一化，默认 true
}

响应：
{
  "vectors": [[0.1, 0.2, ...], ...],  // 与 inputs 一一对应
  "dimension": 2048,
  "model": "jina-embeddings-v4"
}
```

### 3.3 维度查询

```
GET /dimension
→ 200 { "dimension": 2048 }
```

### 3.4 模型状态

```
GET /status
→ 200 {
  "model_loaded": true,
  "model_path": "/path/to/model",
  "device": "cuda",
  "dimension": 2048,
  "load_time_ms": 3200
}
```

## 4. 主后端改造点

### 4.1 capability.py（核心改造）

当前 `get_provider()` 返回本地 provider 实例。改为返回一个 `RemoteInferenceProvider`，内部通过 HTTP 调推理服务：

```python
# backend/vector_engine/remote_provider.py（新增）
class RemoteInferenceProvider(EmbeddingProvider):
    def __init__(self, base_url: str):
        self.base_url = base_url  # 如 http://127.0.0.1:8100
        self._available = None

    def _check_health(self) -> bool:
        try:
            r = requests.get(f"{self.base_url}/health", timeout=3)
            return r.status_code == 200
        except:
            return False

    def is_available(self) -> bool:
        if self._available is None:
            self._available = self._check_health()
        return self._available

    def encode(self, inputs, input_type="text", normalize=True):
        # POST /encode，返回 vectors
        ...

    def get_dimension(self) -> int:
        r = requests.get(f"{self.base_url}/dimension", timeout=3)
        return r.json()["dimension"]
```

`capability.py` 的 `get_provider()` 逻辑改为：
```python
def get_provider():
    global _provider_instance
    if _provider_instance is None:
        config = settings.get_config()
        inference_url = getattr(config, "INFERENCE_SERVICE_URL", None)
        if inference_url:
            from .remote_provider import RemoteInferenceProvider
            _provider_instance = RemoteInferenceProvider(inference_url)
        else:
            # 回退到本地 provider（向后兼容）
            _provider_instance = _create_local_provider()
    return _provider_instance
```

### 4.2 配置项新增

在 `config.yaml` 中新增：

```yaml
INFERENCE_SERVICE_URL: "http://127.0.0.1:8100"  # 推理服务地址，为空则回退本地
INFERENCE_SERVICE_TIMEOUT: 30  # 编码超时（秒）
INFERENCE_SERVICE_ENABLED: true  # 是否启用远程推理
```

### 4.3 搜索链路（similar_search.py / unified_search.py）

这两处通过 `is_vector_enabled()` 判断向量是否可用。改造后 `is_vector_enabled()` 会检查推理服务 health，不可用时返回 False，前端相应置灰"相似搜索"入口。

### 4.4 上传链路（analyze_upload_image → image_analysis）

上传时的自动向量化（`generate_vector.py`）改为调推理服务 `/encode`。视觉分析（`image_analysis.py`，走 glm-4.6v-flash API）不受影响，留在主后端。

### 4.5 system.py（状态接口）

`/api/v1/system/vector-status` 和 `/api/v1/system/vector-engine-status` 改为同时报告：
- 推理服务连接状态（health check）
- 本地向量存储状态（sqlite-vec 连接）
- 当前模式（remote / local）

## 5. 优雅降级策略

| 场景 | 主后端行为 | 前端表现 |
|------|-----------|---------|
| 推理服务正常 | 所有功能可用 | 正常 |
| 推理服务不可用 | CRUD/浏览/标签正常；向量接口返回 503 + 明确错误信息 | 相似搜索/自动打标置灰，tooltip 提示"推理服务离线" |
| 推理服务超时 | 返回 504，不阻塞其他请求 | 同上，Toast 提示 |
| 主后端启动时推理服务未就绪 | 正常启动，不等待 | 正常，功能按需降级 |

**关键原则**：主后端启动和运行**不依赖**推理服务可用性。

## 6. 实施步骤

1. 移除主后端中不再使用的本地 provider import

## 7. 风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| 网络延迟影响编码性能 | 推理服务部署在同一台机器（localhost），延迟 <1ms |
| 推理服务崩溃导致功能不可用 | 优雅降级 + health check + 前端提示 |
| 模型加载失败 | 推理服务启动时捕获异常，`/health` 返回 503 |
| 向后兼容 | `INFERENCE_SERVICE_URL` 为空时回退本地 provider |
| 端口冲突 | 8100 默认，可通过配置修改 |
